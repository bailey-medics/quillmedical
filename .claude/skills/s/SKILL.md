# Explain the issue in simple terms

- The user wants to understand the issue just discussed in the
  conversation: what went wrong, why, and what the fix does.
- If the conversation holds no issue to explain, ask which one they mean
  rather than guessing.
- Write for a reader of around 16 years old. No jargon; where a technical
  word cannot be avoided, say what it means in plain words.
- Use an everyday comparison where it helps, such as turning a page in a
  book that is already open.
- The user is dyslexic. Do not use abbreviations; if one is unavoidable,
  spell out what it stands for in brackets.
- Give the shape first: how many separate problems there were, and how
  they connect.
- One short paragraph for each problem, under a bold lead-in, then one
  for the fix.
- No code, file paths or line numbers unless asked for.
